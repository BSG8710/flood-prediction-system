# FloodGuard — Flood Prediction System

A rebuilt, production-quality version of the flood prediction project: a
scikit-learn/XGBoost model comparison pipeline behind a clean Flask API,
with a modern, responsive web interface.

## What was fixed from the original project

- **`app.py`** had bare comment lines missing `#` (e.g. a line just saying
  `1. Load the saved model and scaler`), which is a `SyntaxError` in Python.
  It also had `float(prediction_proba[1])  100` — a missing `*` operator.
- **`train.py`** had the same missing-`#` problem throughout, indentation
  that fell outside the function body, `"="50` instead of `"="*50`, and it
  pointed at a `flood_prediction.csv` that didn't exist (the real dataset is
  an `.xlsx` file with different column names).
- **`static/script.js` was completely empty** — the prediction form had no
  JavaScript at all, so it could never actually call the backend.
- The project was a single flat folder with no separation between the ML
  pipeline, the web layer, and configuration, and the UI was a single
  hard-coded HTML/CSS pair with no result page logic wired up.

Everything below is a clean rebuild, not a patch — but the ML approach
(train several classifiers, compare, keep the best, serve it through Flask)
is preserved and improved.

## Dataset

`data/flood_dataset.xlsx` — 115 records with these columns:

| Column | Meaning |
|---|---|
| `Temp` | Average temperature (°C) |
| `Humidity` | Relative humidity (%) |
| `Cloud Cover` | Cloud cover (%) |
| `ANNUAL` | Annual rainfall (mm) |
| `Jan-Feb`, `Mar-May`, `Jun-Sep`, `Oct-Dec` | Seasonal rainfall totals (mm) |
| `avgjune` | Average June rainfall (mm) |
| `sub` | Subdivision rainfall index |
| `flood` | Target: 1 = flood occurred, 0 = no flood |

The classes are imbalanced (99 "no flood" vs 16 "flood" rows), which is why
the training pipeline uses `class_weight="balanced"` / `scale_pos_weight`
and selects the best model by **F1-score** rather than raw accuracy.

## Setup

Requires Python 3.12.

```bash
cd flood_system
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## 1. Train the model

```bash
python train.py
```

This will:
1. Load `data/flood_dataset.xlsx`
2. Save EDA charts (class balance, correlation heatmap) to `static/img/`
3. Clean the data (median-impute any missing values, IQR-clip outliers)
4. Split train/test (80/20, stratified) and scale features
5. Train Decision Tree, Random Forest, KNN, and XGBoost
6. Print an Accuracy / Precision / Recall / F1 comparison + confusion matrix
7. Save a model-comparison bar chart and the best model's confusion matrix
8. Save the winning model + scaler + `metadata.json` to `models/`

On this dataset, Decision Tree and Random Forest tie for best F1-score
(~95.6% accuracy, 100% precision, 66.7% recall on the small test split) —
whichever the run selects gets saved automatically.

## 2. Run the web app

```bash
python app.py
```

Visit **http://localhost:5000**

- `/` — landing page with live model stats and training charts
- `/predict` — enter weather data, get an instant flood/no-flood prediction
  with a probability breakdown (no page reload — the result renders via AJAX)
- `/history` — the last 50 predictions, pulled from the database

Every prediction is written to a local SQLite database
(`instance/flood_system.db`) across four tables that mirror the project's
ERD: `users`, `weather_data`, `ml_models`, `prediction_results`. A "guest"
user is created automatically since this rebuild doesn't include a login
system — the schema supports adding real accounts later without changes to
the prediction logic.

## Re-training with new data

Replace `data/flood_dataset.xlsx` (keep the same column names) and re-run
`python train.py`. The next time you start `app.py`, it automatically syncs
the `ml_models` table with whatever `metadata.json` says is the current best
model.

## Notes

- The dev server (`python app.py`) is for local development only. For
  production, run it behind a WSGI server such as `gunicorn app:app`.
- If you see "Model not available" on the `/predict` page, it means
  `train.py` hasn't been run yet (or `models/` was deleted).
